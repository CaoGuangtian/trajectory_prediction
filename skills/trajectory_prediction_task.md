# 飞行轨迹预测研究任务说明

本文档面向后续参与本项目的 Codex/AI 代理，用于统一研究目标、数据理解、预处理约束和实验协议。除非用户明确修改，后续实现、分析和文档应以本说明为默认依据。

## 0. 开发环境

当前项目使用的虚拟环境名称为 `traj-pre`。

## 1. 研究目标

研究目标是根据一段历史 ADS-B 轨迹，预测飞机未来的三维飞行轨迹，并重点评估模型对**训练阶段未见过的飞机**的泛化能力。

主要任务定义：

- 输入：飞机过去一段时间内的位置序列及可用辅助特征；
- 输出：未来一段时间内的三维位置序列；
- 主高度标签：`geoAltitude`（几何高度）；
- 主评估场景：测试集中的飞机 ID 不得出现在训练集或验证集中；
- 第一版模型不使用 `aircraft` ID 作为输入特征。

## 2. 数据集理解

LocaRDS/OpenSky 数据包含八个约一小时的非连续子集。不同子集来自不同日期或时段，不能将其时间直接连接。

主文件 `set_X.csv` 中：

- 一行表示一次 ADS-B 位置报告广播事件；
- `aircraft` 是匿名飞机/发射机标识；
- `timeAtServer` 用于子集内部的排序和相对时间计算，不是完整的日历时间；
- `latitude`、`longitude` 是飞机报告的位置；
- `geoAltitude` 是几何高度；
- `baroAltitude` 是气压高度；
- `numMeasurements` 是收到该广播的地面接收站数量；
- `measurements` 中每项为接收站 ID、信号到达时间和 RSSI，它们不是额外的轨迹点。

辅助文件：

- `set_X_aircraft.csv` 提供按飞机划分的位置可信度标记 `trusted`；
- `set_X_sensors.csv` 提供接收站位置、设备和同步/可信信息。

注意：

- `trusted=True` 表示飞机报告的位置通过独立验证，适合作为高质量标签；
- `trusted=False` 表示未通过验证或位置质量较低；
- 缺失的 `trusted` 通常表示无法验证，不能直接等同于 `False`；
- 同一 `aircraft` 可能出现在多个子集中，但这些记录不构成跨子集的连续轨迹；
- 单个一小时子集中的轨迹可能在开始或结束处被截断；
- 项目中的精简样本只用于格式理解和代码调试，正式结论必须基于足够规模的完整数据。

## 3. 预测坐标与标签

模型内部优先使用局部东-北-天坐标系 ENU，而不是直接回归原始经纬度。

默认处理方式：

1. 将 `latitude`、`longitude`、`geoAltitude` 转换为三维空间坐标；
2. 以历史窗口最后一个有效点作为局部坐标原点；
3. 将历史轨迹和未来标签表示为局部 `(E, N, U)`；
4. 模型预测未来相对于历史末点的三维位移；
5. 需要输出地理坐标时，再转换回经纬度和几何高度。

可进一步按历史末端航向旋转局部坐标，以减小绝对飞行方向对未见飞机泛化的影响。航向应通过多个历史点稳健估计，不能仅依赖两个可能含噪的相邻点。

`baroAltitude` 可作为辅助输入特征，但不能在缺少标记的情况下与 `geoAltitude` 混合作为同一个标签。可考虑增加：

```text
altitude_difference = geoAltitude - baroAltitude
```

## 4. 暂定实验协议

第一版主实验暂定为：

```text
历史观测长度：60 秒
未来预测时域：30 秒
目标采样间隔：1 秒
预测目标：未来 ENU 三维相对位移
主标签高度：geoAltitude
主要训练数据：trusted=True
```

以下配置作为敏感性或消融实验候选：

- 历史长度：30 秒、60 秒；
- 预测时域：10 秒、30 秒、60 秒；
- 均匀重采样与保留不等时间间隔的对比；
- 仅几何位置与加入气压高度、`delta_t`、数据质量特征的对比。

这些数值是研究默认值，不是不可修改的最终结论。正式固定前，必须通过数据分析确认每种配置能够生成足够多的有效轨迹样本。

## 5. 时间处理与轨迹切分

所有轨迹处理必须至少按以下键排序和分组：

```text
subset + aircraft + timeAtServer
```

不得跨子集连接轨迹。对每个分组计算相邻记录时间差 `delta_t`，并同时检查空间跳变、速度和高度变化。

轨迹应在以下情况切分：

- `timeAtServer` 不再单调递增；
- 相邻记录存在较长时间缺口；
- 推算水平速度、垂直速度或加速度明显不合理；
- 位置发生无法由正常飞行解释的跳跃。

长缺口阈值不得凭经验直接写死，应先根据各完整子集的 `delta_t` 分布确定，并在实验配置中记录。

## 6. 重采样原则

第一版基线实验建议使用均匀重采样，以便构造固定长度批次和公平比较模型。

约束如下：

- 只允许对短缺口插值；
- 长缺口必须切分轨迹，禁止跨越插值；
- 优先在 ENU/ECEF 等米制坐标中插值，不直接在经纬度角度上做长距离插值；
- 保存原始点/插值点掩码，必要时作为模型输入或用于消融；
- 保存原始 `delta_t`，不要在重采样后丢失时间质量信息。

后续可实现不等间隔版本，将 `delta_t` 作为输入，评估重采样带来的影响。

## 7. 未见飞机泛化的数据划分

必须在生成滑动窗口之前，按 `aircraft` ID 完成训练、验证、测试划分。全体子集中的同一飞机必须始终属于同一个分区。

必须满足：

```text
train_aircraft ∩ validation_aircraft = ∅
train_aircraft ∩ test_aircraft = ∅
validation_aircraft ∩ test_aircraft = ∅
```

禁止事项：

- 禁止随机拆分单条记录；
- 禁止先生成高度重叠的滑动窗口再随机拆分；
- 禁止使用完整数据计算归一化参数；
- 禁止将飞机 ID 嵌入作为第一版模型输入。

归一化器、异常阈值中的数据驱动统计量以及其他拟合型预处理步骤，只能在训练集上拟合，再应用于验证集和测试集。

除按飞机划分的主实验外，可增加更严格的跨子集/跨时间段测试，用于评估时间和空间分布变化下的泛化能力。

## 8. 数据特性分析要求

正式建模前必须完成以下分析：

### 8.1 规模与可用样本

- 每个子集的记录数、飞机数和可信飞机比例；
- 每架飞机的点数、观测时长和轨迹段数量；
- 不同历史长度与预测时域下可生成的有效样本数量；
- 训练、验证、测试三部分的飞机数和轨迹分布。

### 8.2 时间质量

- `timeAtServer` 范围；
- `delta_t` 分布；
- 重复时间、乱序记录和长缺口比例；
- 重采样前后的有效数据保留率。

### 8.3 空间与运动特性

- 轨迹经纬度密度和接收站覆盖地图；
- 水平速度、垂直速度、加速度和转向率分布；
- 异常位置跳跃和轨迹碎片化情况；
- 不同高度区间和可能飞行阶段的数据分布。

### 8.4 高度与数据质量

- `geoAltitude`、`baroAltitude` 的缺失率和异常值；
- 两种高度差值及其时间变化；
- `trusted=True`、`False` 和缺失三类数据的质量差异；
- 重复记录、缺失值和各字段异常范围。

### 8.5 接收站观测偏差

- `numMeasurements` 分布；
- 接收站数量、覆盖范围与轨迹完整性的关系；
- RSSI 和传感器时间信息是否具有稳定的辅助价值。

## 9. 基线、模型与评价指标

复杂模型之前必须建立简单基线：

- 最后位置保持不变；
- 匀速外推；
- 可选的匀加速或恒定转率运动模型；
- 第一版序列模型可使用 LSTM/GRU，再与更复杂模型比较。

评价指标至少分别报告：

- 水平 ADE 和 FDE，单位米；
- 垂直 MAE/RMSE，单位米；
- 三维 ADE 和 FDE，单位米；
- 不同预测时刻上的误差曲线；
- 不同高度、轨迹长度或飞行状态下的分组结果。

不得只报告单一三维误差，因为它可能掩盖水平和垂直方向表现的显著差异。

## 10. 第一阶段完成标准

进入复杂模型开发前，项目至少应完成：

1. 完整数据的字段和质量报告；
2. 可复现的轨迹分组、切分和重采样流程；
3. 严格按飞机隔离的训练/验证/测试清单；
4. ENU 坐标转换和逆转换测试；
5. 至少一个简单运动学基线；
6. 能回答以下问题的统计结果：

> 在指定历史窗口和预测时域下，可以获得多少条连续、可信、相互独立且来自未重叠飞机集合的训练、验证和测试轨迹？

如果有效样本数量或连续性不足，应优先调整采样间隔、历史长度、预测时域或数据来源，而不是直接增加模型复杂度。
