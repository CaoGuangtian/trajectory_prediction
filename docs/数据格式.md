## 1. OpenSky 数据集

数据位置：`data/openskyDataset/subset_1/`

当前 `subset_1` 解压后包含以下文件：

| 文件 | 作用 | 备注 |
| --- | --- | --- |
| `set_1.csv` | 主轨迹/观测数据表 | 约 1.22 GB，包含飞机位置、高度和传感器测量列表 |
| `set_1_aircraft.csv` | 飞机编号辅助表 | 可用于判断飞机编号是否可信 |
| `set_1_sensors.csv` | 传感器/接收站辅助表 | 包含每个传感器的位置、高度、类型和质量标记 |
| `NOTE.txt` | 数据说明 | 说明该 subset 中部分飞机位置缺失 |
| `LICENSE.txt` | 许可证 | 使用数据前需要保留并遵守许可证要求 |

### 1.1 `set_1.csv`

CSV 表头如下：

```csv
id,timeAtServer,aircraft,latitude,longitude,baroAltitude,geoAltitude,numMeasurements,measurements
```

字段含义：

| 字段 | 类型/示例 | 含义 | 注意事项 |
| --- | --- | --- | --- |
| `id` | `1` | 观测记录编号 | 单行观测的唯一序号 |
| `timeAtServer` | `0`, `0.000999927520751953` | 服务端接收到该记录的相对时间 | 单位需结合数据集说明确认；目前样本表现为从 0 开始的相对时间 |
| `aircraft` | `304` | 飞机编号 | 与 `set_1_aircraft.csv` 的 `aircraft` 字段关联 |
| `latitude` | `52.3788757324219` | 纬度 | WGS84，经纬度单位为度 |
| `longitude` | `-0.659866333007813` | 经度 | WGS84，经纬度单位为度 |
| `baroAltitude` | `6355.08` | 气压高度 | 单位为米 |
| `geoAltitude` | `6286.5` | 几何高度 | 单位为米，可能与气压高度不同 |
| `numMeasurements` | `4` | 当前记录关联的传感器测量数量 | 应与 `measurements` 数组长度一致 |
| `measurements` | `[[208,962354640,98], ...]` | 传感器测量数组 | 字符串形式保存的嵌套数组，每个子数组可理解为 `[sensor_serial, timestamp_ns, signal_strength]`；第一项可与 `set_1_sensors.csv.serial` 关联，第二项为统一到纳秒单位的连续时间戳，第三项为接收信号强度/质量类指标 |

示例数据：

```csv
1,0,304,52.3788757324219,-0.659866333007813,6355.08,6286.5,4,"[[208,962354640,98],[466,37145248250,178],[677,17125900083.3333,195],[197,5770127166.66667,109]]"
```

### 1.2 `set_1_aircraft.csv`

CSV 表头如下：

```csv
aircraft,trusted
```

字段含义：

| 字段 | 类型/示例 | 含义 | 注意事项 |
| --- | --- | --- | --- |
| `aircraft` | `1`, `2`, `304` | 飞机编号 | 与 `set_1.csv.aircraft` 关联 |
| `trusted` | 空值或标记值 | 飞机位置/标签可信度标记 | 样本前几行为空，使用前需要检查全表的实际取值范围 |

### 1.3 `set_1_sensors.csv`

CSV 表头如下：

```csv
serial,latitude,longitude,height,type,good
```

字段含义：

| 字段 | 类型/示例 | 含义 | 注意事项 |
| --- | --- | --- | --- |
| `serial` | `1`, `208`, `466` | 传感器编号 | 与 `set_1.csv.measurements` 中每个子数组的第一项关联 |
| `latitude` | `46.68106661` | 传感器纬度 | WGS84，单位为度 |
| `longitude` | `7.66531348` | 传感器经度 | WGS84，单位为度 |
| `height` | `680.9232` | 传感器高度 | 单位为米 |
| `type` | `SBS-3`, `Radarcape`, `dump1090` | 传感器类型 | 可用于筛选不同接收设备 |
| `good` | `TRUE`/`FALSE` | 传感器质量标记 | 可用于过滤低质量传感器 |

### 1.4 OpenSky 使用建议

- 主轨迹序列可按 `aircraft` 分组，并按 `timeAtServer` 排序。
- 建模位置特征可优先使用 `longitude, latitude, geoAltitude` 或 `longitude, latitude, baroAltitude`，两种高度不要混用，需在实验配置中明确。
- 若使用传感器测量信息，需要先把 `measurements` 从字符串解析为数组，再通过 `serial` 关联传感器位置。
- `NOTE.txt` 提到该 subset 部分飞机位置缺失，因此预处理时需要检查 `latitude/longitude/baroAltitude/geoAltitude` 的缺失值。

## 2. 实测数据 2

数据格式已知为 CSV。当前文档中记录的表头如下：

```csv
PARTNO,P1,GP,H,JD,WD,TASK,PLANETYPE,DTRQ
```

示例数据：

```csv
20250301,226106,6272.0,1000,113.5442,34.3134,0,大型机,01-MAR-25 12.01.32.475000 AM
```

字段含义：

| 字段 | 类型/示例 | 含义 | 注意事项 |
| --- | --- | --- | --- |
| `PARTNO` | `20250301` | 飞行日期 | 建议统一解析为 `YYYYMMDD` 或标准日期类型 |
| `P1` | `226106` | 批号/架次编号 | 代表一次飞行，但可能复用；同一天上午/下午两次飞行可能使用同一批号 |
| `GP` | `6272.0` | 暂未完全确认 | 目前样例为数值字段，需结合业务来源确认含义；不要直接丢弃，建议预处理阶段保留 |
| `H` | `1000` | 高度 | 需确认单位；从旧 LSTM 预处理代码看，后续会作为高度维度参与坐标转换 |
| `JD` | `113.5442` | 经度 | 当前样例看起来是度分格式或压缩格式，旧预处理代码里存在 DMS 转十进制度逻辑，入库前需统一为十进制度 |
| `WD` | `34.3134` | 纬度 | 字段名是 `WD`，表示纬度；同样需要统一坐标格式 |
| `TASK` | `0` | 任务编号 | 可作为任务/场景标签 |
| `PLANETYPE` | `大型机` | 机型 | 分类字段，注意编码使用 UTF-8 |
| `DTRQ` | `01-MAR-25 12.01.32.475000 AM` | 轨迹点采样时间 | 建议统一解析为标准时间戳，并与 `PARTNO` 共同校验日期 |

### 2.1 实测数据的轨迹唯一标识

由于 `P1` 可能复用，建议不要只用 `P1` 作为一条轨迹的唯一 ID。更稳妥的轨迹键可以按实际数据情况组合：

```text
trajectory_id = PARTNO + P1 + TASK + PLANETYPE + 起止时间段
```

如果同一天同批号存在上午/下午两次飞行，可以根据 `DTRQ` 的时间间隔把轨迹拆分为不同段。

### 2.2 实测数据进入模型前的建议标准格式

为了和 LSTM 预处理流程衔接，建议将实测数据先标准化为以下列：

```csv
ID,H,Lon,Lat,Time
```

对应关系：

| 标准列 | 来源字段 | 说明 |
| --- | --- | --- |
| `ID` | 由 `PARTNO/P1/TASK/PLANETYPE/DTRQ` 组合生成 | 一条连续轨迹的唯一编号 |
| `H` | `H` | 高度，统一单位后保存 |
| `Lon` | `JD` | 经度，统一为十进制度 |
| `Lat` | `WD` | 纬度，统一为十进制度 |
| `Time` | `DTRQ` | 采样时间，建议统一为 `YYYYMMDD HH:mm:ss.SSS` |

## 3. 模型训练样本格式

旧 LSTM 代码中使用的中间训练样本通常位于类似目录：

```text
data/generate_samples/input-60_output-10_timestep-1_zscore_*/
```

常见文件：

| 文件 | 含义 |
| --- | --- |
| `train_x.csv` / `train_y.csv` | 训练集输入序列/预测目标序列 |
| `val_x.csv` / `val_y.csv` | 验证集输入序列/预测目标序列 |
| `test_x.csv` / `test_y.csv` | 测试集输入序列/预测目标序列 |
| `train_ids.csv` / `val_ids.csv` / `test_ids.csv` | 每个滑动窗口对应的轨迹 ID |
| `mean.csv` / `std.csv` | z-score 归一化参数，顺序通常为 `[e, n, u]` |
| `max.csv` / `min.csv` | min-max 归一化参数，顺序通常为 `[e, n, u]` |
| `train_data_raw.csv` | 归一化前的训练数据展开结果 |

序列约定：

- 原始经纬高通常先转换为 ENU 坐标，即东、北、天三个维度：`e, n, u`。
- `train_x.csv` 和 `train_y.csv` 通常是二维展开表，需要按参数 reshape：

```text
train_x -> (num_samples, input_seq_len, 3)
train_y -> (num_samples, pred_steps, 3)
```

- 当前 LSTM 脚本常见配置为 `input_seq_len=60`、`pred_steps=10` 或 `20`，具体以生成目录名和训练参数为准。
